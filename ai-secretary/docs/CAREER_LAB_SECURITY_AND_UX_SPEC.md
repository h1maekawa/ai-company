## 1. 概要と背景

「就活攻略ラボ」のSNS自動化基盤（X/Instagram）において、コード静的解析および実運用シミュレーションを実施した結果、以下の3カテゴリにおける潜在的脆弱性・堅牢性の懸念およびUXのボトルネックが特定された。

1. **可用性・セキュリティ（SEC）**: 環境変数による過剰拒否、LLM出力のJSONパース耐性、ファイル更新時の破損保護。
2. **編集・操作UX（UX）**: `window.prompt` による劣悪な編集体験、文字数・改行の視認性欠如。
3. **運用効率（OPS）**: 35枚スライドの一括生成機能の欠如、ナレッジ選択の手動負荷、画像Stale状態の可視化不足。

本要件書に基づき、ユーザーの就寝中に自動で改修を完了させ、堅牢かつ洗練されたプロダクトOSへと昇華させる。

---

## 2. 機能要件 (Requirements)

### セキュリティ & 堅牢性要件
- **REQ-SEC-001 [可用性] GITHUB環境変数過剰ブロッキングの解消**:
  - `store.ts` 内の `localFile()` は、他機能（Engineering Worker等）のために `.env.local` に `GITHUB_TOKEN` 等が設定されていても、Careerデータを常にローカルパス (`memory/personal/career/career-state.json`) へ安全に読み書きし、不当な例外（`CAREER_PRIVATE_STORE_REQUIRES_LOCAL_VAULT`）で停止しないこと。
- **REQ-SEC-002 [堅牢性] Ollama JSON出力の堅牢なサニタイズ**:
  - ローカルLLMがマークダウンコードブロック（```json ... ```）や前後に思考ログ・解説テキストを付与した場合でも、正規表現により純粋なJSONオブジェクトを抽出し、確実にパースすること。
- **REQ-SEC-003 [データ保護] 状態ファイルの自動バックアップと破損防止**:
  - 状態保存時、書き込み前に直前状態を `.bak` として保持し、JSON破損時の安全リカバリを担保すること。

### UX & 運用性要件
- **REQ-UX-001 [編集体験] インライン編集モーダルの導入**:
  - `window.prompt` を完全廃止。
  - X投稿本文（280文字カウント）、Instagramスライド5枚（見出し・本文の各入力、リアルタイム文字切れ警告）、キャプション（2200文字カウント）を1つの見やすいモーダルで編集可能にすること。
  - 編集により承認が自動失効（`review` へリセット）することをUI上で明示。
- **REQ-UX-002 [一括操作] 週次バッチ（35枚）一括画像レンダリング**:
  - 1クリックで週次バッチ内の全Instagram投稿（7投稿×5枚＝35枚）のPNGを連続レンダリングし、進捗を表示するAPIおよびUIボタンを提供すること。
- **REQ-UX-003 [操作短縮] ナレッジのワンクリック一括選択**:
  - 週次生成に必要な異なる7テーマのナレッジをワンクリックで自動選択する補助機能を提供すること。
- **REQ-UX-004 [可視化] 画像Stale（陳腐化）警告表示**:
  - 投稿編集後に最新の `contentHash` と生成済み画像のハッシュが不一致となった場合、UI上に「画像要更新」バッジを表示すること。

## 3. 受入基準 (Acceptance Criteria)

- **AC-001**: `GITHUB_TOKEN` が設定された環境でも、`loadCareerState()` / `saveCareerState()` が正常に動作し、ローカルファイルに永続化されること。
- **AC-002**: コードブロック付きのOllama JSONレスポンスが正常にパースされ、投稿生成が完走すること。
- **AC-003**: 投稿編集がモーダルUIで完結し、改行や長文が正常に保存され、承認が確実に失効すること。
- **AC-004**: バッチ一括レンダリングAPIが7投稿35枚のPNGを安全に生成すること。
- **AC-005**: 既存テスト223件を含め、`npm run test:career`、`npm run typecheck`、`npm test`、`npm run build` がすべて成功すること。

## 4. 自動テスト項目

1. `store.test`: GITHUB環境変数が存在してもローカルストアが正常にロード・セーブできることの検証。
2. `ollama.test`: コードフェンス付きJSONレスポンスの抽出・パース処理の検証。
3. `images.batch.test`: バッチ単位の画像一括生成APIの安全性とステータス検証。
4. `ux.edit.test`: 編集後のStale検知および承認失効のデータ整合性検証。
