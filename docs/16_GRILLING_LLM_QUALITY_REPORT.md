- 本システムの主要な目的は、知的作業者・意思決定者の「思考と行動の統合」とする。 — 知的作業者・意思決定者にとって最も重要な課題解決と目標達成に貢献するため。個人のタスク消化効率化、チームの共同作業効率化、特定のビジネスプロセス最適化に特化するのではなく、より広範な知的活動全体をカバーする。
- 本システムの主要な対象ユーザーは「知的作業者・意思決定者」とする。 — 彼らが直面する思考と行動の統合という課題に特化して価値を提供するため。一般的な個人利用者、小規模チーム、大規模組織のメンバーを主たる対象とはしない。
- タスクは「階層化されたプロジェクト要素 / 意思決定ステップ」として定義し、その粒度で管理する。 — 思考と行動の統合を促進するためには、単なるToDoアイテムではなく、プロジェクトや意思決定の構造を反映したタスク定義が必要である。シンプルなToDoアイテムや特定の調査・執筆項目に限定せず、より柔軟な粒度を許容する。
- 既存の主要4システム（Knowledge基盤、Morning Planning、Grilling Session、Skills Registry）とは「密連携（データ共有 / 機能埋め込み）」を行う。 — 思考と行動の統合という目的を達成するためには、既存システムとの深い連携が不可欠である。疎連携や限定連携、独立システムでは不十分であると判断された。Fund Policy Engine, Investing, Note事業部との密連携は初期スコープから外す。
- タスクの状態遷移は「カスタマイズ可能」なワークフローモデルとして設計する。 — 知的作業者・意思決定者の多様な思考プロセスやプロジェクトの特性に合わせて柔軟に対応できるようにするため。シンプルな3段階やアジャイルボード型、Grillingのステータスに準拠する固定的なワークフローでは対応できない。
- タスクに付与できる情報は「Knowledge基盤からの情報リンク/埋め込み + カスタムフィールド」とする。 — 思考の文脈をタスクに直接反映させ、意思決定の根拠や背景を明確にするため。固定項目のみ、タグ/カテゴリ、詳細説明文に限定せず、拡張性を持たせる。
- 時間・リソース管理は「タイムブロッキング統合 + リソース（スキル）割り当て」として設計する。 — Morning Planningとの連携により行動計画を具体化し、Skills Registryとの連携により適切なリソース配分を可能にするため。期限日のみ、開始/終了日+見積もり時間、実績時間記録のみでは不十分である。
- Grilling Sessionとの連携を通じて、「Grillingのサブステップとしてタスクを管理 + 意思決定結果をタスク化し自動生成」する。 — 意思決定プロセスから行動へのスムーズな移行を支援し、思考の結果を行動に直結させるため。
- Grillingのサブステップとタスクのワークフローは、「Grillingのサブステップはタスクのコンテキストとして機能し、タスクのWFは独立」して動作する。 — Grillingのフェーズ進行がタスクの進行に影響を与えつつも、タスク自体の進捗管理は独立して行える柔軟性を持たせるため。タスクのWFがGrillingのステータスに完全に準拠すると、タスク固有の進捗管理が困難になるため。
