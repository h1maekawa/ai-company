# Googleカレンダー連携の設定

朝会（`/planning`）で作ったタイムブロッキングを、Googleカレンダーへ自動同期するための一度きりの設定です。
**設定しなくても「ICSファイルでダウンロード」は今すぐ使えます**（ダウンロードしたファイルを開けばカレンダーに取り込まれます）。自動同期が要るときだけ以下を行ってください。

所要時間：10分程度。すべてご自身のGoogleアカウントでの操作になります。

---

## 1. Google Cloudでプロジェクトとカレンダー APIを用意する

1. https://console.cloud.google.com/ を開く
2. 上部のプロジェクト選択 → 「新しいプロジェクト」→ 名前は `ai-company` などで作成
3. 検索窓で「Google Calendar API」→ **有効にする**

## 2. OAuth同意画面

1. 左メニュー「APIとサービス」→「OAuth同意画面」
2. User Type は **外部** を選択して作成
3. アプリ名（例：`AI Company`）とご自身のメールアドレスを入力して保存
4. 「対象」（Audience）で **テストユーザー** にご自身のGoogleアカウントを追加
   - 公開申請は不要です。テストユーザーのままで動きます

## 3. OAuthクライアントIDを作る

1. 「APIとサービス」→「認証情報」→「認証情報を作成」→ **OAuth クライアント ID**
2. アプリケーションの種類：**デスクトップアプリ**
3. 作成後に表示される **クライアントID** と **クライアントシークレット** を控える

> デスクトップアプリ種別にしておくと、次のリフレッシュトークン取得が一番簡単です。

## 4. リフレッシュトークンを取得する

1. https://developers.google.com/oauthplayground/ を開く
2. 右上の⚙️（設定）→ **Use your own OAuth credentials** にチェック
   → 手順3のクライアントID・シークレットを入力
3. 左のリストから **Calendar API v3** → `https://www.googleapis.com/auth/calendar` を選択
4. **Authorize APIs** → **プライベート側のアカウント（`h1maekawa123@gmail.com`）で許可**
   （「このアプリは確認されていません」と出たら「詳細」→「（アプリ名）に移動」で進めます）

   > ⚠️ ここは必ず**プライベート側**で認証してください。理由は次の「共有設定」に書いています。
5. **Exchange authorization code for tokens** を押す
6. 表示された **Refresh token** を控える

## 5. 環境変数を設定する

Vercel（本番）と `ai-secretary/.env.local`（ローカル）の両方に設定します。

```
GOOGLE_CLIENT_ID=<手順3のクライアントID>
GOOGLE_CLIENT_SECRET=<手順3のクライアントシークレット>
GOOGLE_REFRESH_TOKEN=<手順4のリフレッシュトークン>
GOOGLE_CALENDAR_ID_WORK=hiroyuki.maekawa@crestix-inc.com
GOOGLE_CALENDAR_ID_LIFE=h1maekawa123@gmail.com
```

- 💼仕事のタスクは `GOOGLE_CALENDAR_ID_WORK`、🏠生活のタスクは `GOOGLE_CALENDAR_ID_LIFE` へ入ります
- 2つを分けた場合、**仕事の時間帯はプライベート側にも「仕事」とだけ入れて塞ぎます**（内容は書きません）
- 分けない場合は `GOOGLE_CALENDAR_ID`（既定 `primary`）だけでも動きます
- Vercelは環境変数の追加後に **再デプロイ** が必要です

### 2つのアカウントを1つのトークンで書くための共有設定

書き込めるのは `GOOGLE_REFRESH_TOKEN` を発行したアカウントの権限の範囲だけです。
もう一方のカレンダーにも入れるには、**そのカレンダーを共有**する必要があります。

そして共有すると、**共有された側のカレンダー一覧にそのカレンダーが並びます**。
つまり「どちらを共有するか」で、どちらの予定が相手に見えるかが決まります。

#### 仕事アカウントに個人の予定を見せたくない場合（推奨）

**プライベート側で認証し、仕事カレンダーをプライベート側へ共有します。**
こうすると仕事アカウントはプライベートカレンダーへのアクセス権を一切持ちません。

1. 手順4のリフレッシュトークンを **`h1maekawa123@gmail.com`** で取得する
2. **仕事側**（`hiroyuki.maekawa@crestix-inc.com`）でGoogleカレンダーを開く
3. 左の「マイカレンダー」→ 対象カレンダーの「⋮」→ **設定と共有**
4. 「特定のユーザーやグループと共有する」→ **ユーザーを追加** → `h1maekawa123@gmail.com`
5. 権限を **「予定の変更権限」** にする（「閲覧権限」では書き込めません）

これで、

- 仕事アカウントから見えるのは仕事カレンダーだけ（個人の予定は一切見えない）
- プライベートアカウントからは両方見える（本人だけなので問題なし）

#### 逆向きにした場合の注意

仕事アカウントで認証してプライベートカレンダーを共有すると、
**仕事アカウントのカレンダー一覧に個人の予定が表示されます**。
既にその設定にしてしまった場合は、プライベートカレンダーの「設定と共有」から
仕事アカウントを**削除**し、上の推奨手順に切り替えてください。

## 6. 動作確認

`/planning` で時間割を生成し、**📅 Googleカレンダーへ同期** を押します。
「Googleカレンダーへ◯件同期しました」と出れば完了です。

---

## 挙動のメモ

- 同期は**その日の分を作り直す**方式です。アプリが作ったイベントだけを消してから入れ直すので、時間割を作り直しても古いブロックが残りません
- 手動で入れた予定や他アプリの予定は消しません（このアプリが作った印のあるイベントだけを対象にします）
- タイムゾーンは Asia/Tokyo 固定です
- プライベート側の「仕事」ブロックは非公開（visibility: private）で作ります。カレンダーを共有している相手にも中身は見えません
- 未分類のタスクは仕事カレンダー側へ入ります

## うまくいかないとき

| 症状 | 対処 |
| --- | --- |
| 「Googleの認証に失敗しました（400）」 | リフレッシュトークンが失効。手順4をやり直す |
| 「Googleカレンダー連携が未設定です」 | 環境変数が読めていない。Vercelなら再デプロイが必要 |
| 同期は成功するが予定が見えない | `GOOGLE_CALENDAR_ID_WORK` / `_LIFE` が別カレンダーを指していないか確認 |
| 片方のカレンダーにだけ入らない | そのカレンダーが認証アカウントへ「予定の変更権限」で共有されているか確認（上の共有設定） |
| 仕事アカウントに個人の予定が見える | 共有の向きが逆。プライベートカレンダーの共有から仕事アカウントを削除し、推奨手順に切り替える |
| プライベート側に仕事の内容が見えてしまう | マスク予定は件名「仕事」・非公開で作ります。詳細が出る場合、その仕事タスクが🏠生活に分類されていないか確認 |
